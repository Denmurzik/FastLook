# FastLook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build FastLook — a native Quick Look-style space-bar file previewer for Windows 11 — from the spike skeleton to a release-ready v1.0.0 (installer, portable zip, CI/release workflows, docs).

**Architecture:** Three executables in one folder plus a static library: `FastLook.exe` (pure Win32 daemon: LL keyboard hook, tray, Explorer queries on a disposable STA thread, Viewer process manager), `FastLook.Viewer.exe` (WinUI 3 unpackaged self-contained: one warm preview window, previewers, settings; trims and exits when idle), `FastLook.PreviewHost.exe` (sacrificial host for shell preview handlers), `FastLook.Core.lib` (no WinUI: all pure logic, unit-tested with GoogleTest). Daemon and Viewer talk over a per-user named pipe with length-prefixed UTF-8 JSON.

**Tech Stack:** C++20, C++/WinRT 3.0, Windows App SDK 2.x (WinUI 3), Win32/COM (Shell, WIC, Direct2D, DirectWrite, Media Foundation via MediaPlayerElement, Windows.Data.Pdf), vcpkg manifest (lexilla, md4c, libarchive, libwebp, nlohmann-json, gtest), MSBuild (VS Build Tools, v145/v143), PowerShell 7 scripts, Inno Setup 6, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-25-fastlook-design.md` (binding). Spike report: `.superpowers/reports/spike-report.md` (local, gitignored).

## Planner decisions

Where the spec is silent (or a literal reading would break a metric), these are decided here; tasks implement them as written.

1. JSON library: `nlohmann-json` added to `vcpkg.json` (settings, IPC, PowerToys files, GitHub API).
2. Animated WebP: plain `libwebp` added to `vcpkg.json` (`WebPAnimDecoder` lives in libwebpdemux, built by default; the `anim` feature only adds tools); static WebP still decodes via WIC.
3. libarchive built with `default-features: false` + `bzip2, lz4, lzma, zstd` (no crypto, no libxml2).
4. MSBuild: `Directory.Build.props` holds properties (out dirs, toolset choice, vcpkg); C++ item definitions live in `build/FastLook.Cpp.props`, imported by every `.vcxproj`.
5. Toolset: `$(FastLookToolset)` = `v143` when `$(VisualStudioVersion)` is `17.0`, else `v145`; `build.ps1 -Toolset` overrides; CI relies on the auto-detection (no hard-coded toolset).
6. vcpkg: `build.ps1` runs `vcpkg install` explicitly into `out/vcpkg_installed`; MSBuild integration with `VcpkgManifestInstall=false`; vcpkg root = `$VCPKG_ROOT` → `$VCPKG_INSTALLATION_ROOT` → VS-bundled `VC\vcpkg`.
7. App-local VC++ runtime (`msvcp140*.dll`, `vcruntime140*.dll`) is copied into the release folder by `package.ps1` (self-contained WinAppSDK does not ship the VCRT).
8. XAML is used only for `App`, `PreviewWindow`, `SettingsWindow` and its three pages, all flat in `src/Viewer/`; previewer UIs are built in C++ code (no per-previewer IDL/XAML).
9. Strings: one `.resw` map per feature (`Strings/<lang>/<Feature>.resw`), looked up with `Str(map, key)`; the daemon uses a compiled-in EN/RU table (no resw in Win32).
10. Project item lists are globs (frozen after Task 1); libraries are linked with `#pragma comment(lib, "...")` in the `.cpp` that needs them; `src/Viewer/pch.h` is frozen after Task 9 (add includes in your own `.cpp`).
11. `TreatWarningAsError=true` for Core, Daemon, PreviewHost, Core.Tests; Viewer stays `false` (generated XAML code) but must add no new warnings from `src/`.
12. Version single source: `src/Common/Version.h`, included by all `.rc` files and by Core.
13. App icon generated by `scripts/make-icon.ps1` → `assets/FastLook.ico` (committed).
14. Settings JSON schema exactly as in Task 3; autostart truth is the HKCU Run value, not stored in settings.json.
15. Test hooks via env vars (read in every build, inert unless set): `FASTLOOK_DATA_DIR` (settings+logs dir), `FASTLOOK_POWERTOYS_DIR`, `FASTLOOK_IDLE_SECONDS` (overrides idle-unload minutes), `FASTLOOK_TEST_STALL_HOOK_MS`, `FASTLOOK_TEST_UI_STALL_MS`, `FASTLOOK_TEST_PREPARE_DELAY_MS`, `FASTLOOK_HOST_DEBUG_HANG` (`1`/`before` or `after-ready`), `FASTLOOK_UPDATE_API`, `FASTLOOK_UPDATE_AUTOCHECK`, `FASTLOOK_E2E=1` (enables Explorer-driving gtests).
16. Portable mode (`portable.txt` next to the exe): `settings.json` and `logs\` next to the exe. The portable zip ships `portable.txt`.
17. IPC: `show` always shows; `toggle` = close if the same item is visible, else show. The daemon sends `toggle` on Space. Added message `items` (two-phase show) and Viewer→daemon `event` (`pinned`, `settingsChanged`). The Viewer answers every daemon request except `ping` (→ `pong`) and `shutdown` with `ack` (`re` = request id; `shown` meaningful for `show`/`toggle`), built on the UI thread.
18. Two-phase show: the daemon sends the selection (or focused item) immediately; the full folder list follows in `items`. Needed for the 50 ms metric with 20 000-item folders.
19. Explorer item enumeration: `IFolderView::Items(SVGIO_* | SVGIO_FLAG_VIEWORDER, IID_IEnumIDList)` in batches of 512, names resolved locally via a bound `IShellFolder`; child PIDLs compared bytewise.
20. Selection sync uses `IShellView::SelectItem(childPidl, SVSI_SELECT|SVSI_DESELECTOTHERS|SVSI_ENSUREVISIBLE|SVSI_FOCUSED)` (by PIDL, not by index — indices differ from view order in grouped views). It runs on the Viewer's own ShellWorker with a 500 ms timeout, and only when navigating a folder list (never while navigating a multi-selection, which would destroy it).
21. Hook focus check is positive: focused HWND class `DirectUIHWND` or `SysListView32` with an ancestor `SHELLDLL_DefView`, plus the spec's negative checks (caret in Edit/RichEdit, menu/move-size modes).
22. Type-ahead keys: `0-9`, `A-Z`, `VK_NUMPAD0-9`, `VK_OEM_1..VK_OEM_8`, `VK_OEM_102`, `VK_OEM_PLUS/COMMA/MINUS/PERIOD` (Cyrillic letters sit on OEM keys), without Ctrl/Alt/Win.
23. Injected events are accepted unless `dwExtraInfo == kInjectedMarker` (`0x464C4B31`), so SendInput-driven e2e tests work.
24. `pong` and `ack` are sent from the Viewer UI thread (a hung UI thread must fail them).
25. Foreground: the Viewer gets focus with the dummy-SendInput trick (marker-tagged unassigned VK `0xE8`) + `SetForegroundWindow`; on close it returns the foreground to the source Explorer window.
26. `--background` prewarm: window moved off-screen, `AppWindow.Show(false)` (no activation), hidden after the first rendered frame (→ `ViewerEvent::PrewarmDone`), trimmed 1 s after that event; never steals focus.
27. The window is shown immediately on the request (no wait for classification or `PrepareAsync`): Loading state, size = the default for `KindForExtension(name)` (text 960×720, other 720×540) or the current size while navigating; the content attaches when `PrepareAsync` finishes and a size change uses the resize animation.
28. Preferred image size = native pixels / monitor scale (1:1 physical pixels).
29. Arrows always navigate (also in text); text scrolls with wheel/PgUp/PgDn/Home/End. Navigation does not wrap around.
30. Ctrl+C copies the CodeView text selection when non-empty, otherwise the file (CF_HDROP).
31. Keys are handled in the window root's `PreviewKeyDown` (tunnelling) so previewer controls (MediaPlayerElement, ScrollViewer) cannot swallow Space/Esc/arrows.
32. LineIndex: checkpoint every 64 lines; CR, LF and CRLF end a line; a run longer than 16 384 units without EOL is split (continuation flag); empty file = 1 line, `"a\n"` = 2 lines.
33. CodeView: a plain `SurfaceImageSource` sized to the viewport in physical pixels (`ActualSize × XamlRoot.RasterizationScale`), recreated on `SizeChanged` and on `XamlRoot.Changed` when the rasterization scale changes; D2D draws with DPI = 96 × scale (documents can exceed surface limits, so no document-sized surface); own vertical `ScrollBar` in line units.
34. Highlighting: token category from `ILexer5::TagsOfStyle`; keyword lists only for the top languages; lexing runs from document start to last visible line + 200 lines on a background thread; UTF-16 files are not highlighted.
35. Markdown: raw HTML blocks/inline HTML are shown as plain monospace text; remote images show alt text; links open only for `http:`, `https:`, `mailto:`.
36. Archive: flat list (no tree); compressed size only for ZIP (delta of `archive_read_header_position`); single-stream `.gz/.bz2/.xz/.zst` listed via the raw format; non-UTF-8 names fall back to the OEM code page.
37. Shell-handler blocklist = known WebView2 CLSIDs + any handler whose server path is under a `PowerToys` or `Microsoft\Edge` directory + MSHTML-based handlers (server file name `inetcomm.dll` or `mshtml.dll`) — "no browser engine" covers PreviewHost too.
38. PreviewHost protocol: command line + stdin/stdout text lines (Task 22). Office handlers registered as `LocalServer32` (WINWORD.EXE/EXCEL.EXE) run outside FastLook's job: never terminated by FastLook, excluded from FastLook's RAM metrics.
39. Job objects with `KILL_ON_JOB_CLOSE | SILENT_BREAKAWAY_OK`: daemon→Viewer and Viewer→PreviewHost (apps launched via "Open" are not killed).
40. Cloud placeholders (`FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS` / `RECALL_ON_OPEN` / `OFFLINE`) are never read: Fallback with shell thumbnail.
41. Previewer `PrepareAsync` timeout 10 s (shell handler has its own 8 s) → fallback.
42. Language change applies after the Viewer restarts (Viewer exits at its next quiet state); theme applies immediately; daemon strings switch immediately.
43. Leak criterion for "1000 opens": Private **Bytes** growth ≤ 2 MB between iteration 100 and 1000 (Private WS after trim is ~0 and cannot show leaks); warm-idle Private WS is reported too.
44. Daemon CLI: `--shutdown`, `--show <path>` (forwarded to the running instance), `--toggle <path>` (same, sends `toggle`; for scripted show/hide loops), `--warm` (start Viewer at launch), `--perf-log <file>`. Viewer CLI in Task 9; Viewer without arguments opens Settings.
45. Release assets: `FastLook-Setup-<v>.exe`, `FastLook-Setup-<v>.exe.sha256`, `FastLook-<v>-portable-x64.zip`, `FastLook-<v>-portable-x64.zip.sha256`; `.sha256` = `<64 lowercase hex><two spaces><file name>\n`.
46. Updater runs `FastLook-Setup-<v>.exe /SILENT /SUPPRESSMSGBOXES /NORESTART`; the installer stops FastLook with `FastLook.exe --shutdown` and relaunches it.
47. Uninstaller asks with a MsgBox whether to delete `%LOCALAPPDATA%\FastLook` (default No; silent uninstall keeps it).
48. CI: `windows-2025` runner, Inno Setup via `choco install innosetup` when `iscc` is missing; NuGet and vcpkg archives cached with `actions/cache`; `release.yml` creates a **draft** release (the lead publishes).
49. Video decode failure → fallback with the HEVC Store link (`9NMZLZ57R3T7`); audio failure → fallback without a link.
50. Daemon threads: main (window, tray, timers), hook thread, controller thread (all shell-worker and pipe calls, each with a timeout), pipe reader thread. The main thread never blocks.
51. Window animation: XAML root visual animated with Composition (scale/translation from icon rect + opacity); Mica frame appears at final size; DWM transitions disabled for the window; resize = stepped `MoveAndResize` ≤ 150 ms when either dimension changes by > 10 %.
52. Animated GIF/WebP/APNG canvases larger than 4096×4096 show the first frame only.
53. Viewer liveness (replaces spec §4.3 "ping before show", which cannot fit the 50 ms metric): no ping on the hot path. `Deliver` sends the request at once and waits for its `ack` (≤ 1500 ms, on the controller thread — the window is already showing); no ack or a disconnect → wait ≤ 2 s for a process exiting on its own, else `TerminateProcess` → relaunch → resend once. Background heartbeat: when the Viewer runs and nothing was heard from it for ≥ 10 s, the controller sends `ping` without waiting; a ping unanswered for > 1500 ms marks the Viewer **stale**, and the next `Deliver` kills and relaunches it before sending. Same detection threshold as the spec (1500 ms, UI-thread-bound reply).
54. Previewer lifetime: previewers are `std::shared_ptr<IPreviewer>` (`IPreviewer` derives from `std::enable_shared_from_this<IPreviewer>`); `PrepareAsync` takes its arguments by value and starts with `auto self = shared_from_this();`; the session calls `Unload()` and drops a previewer only after its (possibly cancelled) `PrepareAsync` has completed — until then it sits in a "retiring" list.
55. GPU device: `DeviceResources` lives for the process; Hide releases only the previewer's own resources (`Unload`). `ReleaseAll()` is used only for device-lost recovery. Warm-idle is measured after use as well (Task 33) to check this.
56. Cloud placeholders: `PreviewItem::cloudPlaceholder` travels to the previewers; the Fallback thumbnail uses `SIIGBF_INCACHEONLY` then `SIIGBF_ICONONLY`; no property-store reads; the Preloader skips placeholders.
57. Update downloads: HTTPS only; allowed hosts `api.github.com`, `github.com`, `objects.githubusercontent.com`, `release-assets.githubusercontent.com` (GitHub asset redirects); a redirect to any other host is rejected.

## Global Constraints

- Windows 11 22H2+ only, x64 only. No Windows 10, no ARM64.
- C++20 (`stdcpp20`), `/permissive-`, `/W4`, C++/WinRT, WinUI 3 (Windows App SDK) unpackaged (`WindowsPackageType=None`) self-contained (`WindowsAppSDKSelfContained=true`). Toolset v145 with fallback to v143.
- vcpkg manifest, triplet `x64-windows-static-md`.
- No WebView2 / browser engine in any FastLook process (daemon, Viewer, PreviewHost): WebView2- and MSHTML-based shell handlers are blocklisted (decision 37). Office handlers that run in their own `LocalServer32` process (WINWORD/EXCEL) live outside FastLook's job and RAM metrics and are never terminated by FastLook.
- `FastLook.exe` is pure Win32: no XAML, no WinRT activation. `FastLook.Core.lib` has no WinUI.
- All three exes in one folder; per-monitor DPI v2 manifest in all three.
- No network requests except the manual update check (HTTPS to `api.github.com` / `github.com`, plus GitHub's asset redirect hosts per decision 57). No background checks.
- Never execute previewed files; SVG only via Direct2D; Markdown never loads remote resources; shell preview handlers only out-of-process in PreviewHost.
- Settings: `%LOCALAPPDATA%\FastLook\settings.json` (versioned, unknown fields preserved, corrupt → `.bak` + defaults). Logs: `%LOCALAPPDATA%\FastLook\logs\`, rotation 2×1 MB, Info level without paths, paths only at Debug.
- Pipe: `\\.\pipe\FastLook-<SID>-v1`, 4-byte little-endian length + UTF-8 JSON.
- UI language EN + RU via `.resw`, system language by default, override in settings. No user-visible literal strings in Viewer code.
- Timeouts/limits (verbatim from spec): hook callback ≤ 50 µs, no COM/allocations/locks in it; rehook every 60 s; heartbeat stale > 5 s → recreate hook thread; type-ahead window 1000 ms; shell worker request 1000 ms; selection sync 500 ms; ping/ack 1500 ms; folder list cap 20 000, otherwise ±5000 around focus; PreviewHost show timeout 8 s; archive 100 000 entries / 2 s; folder stats 5 s; neighbour cache ≤ 3 items (±1, image at target size, first 64 KB of text); PDF ≤ 6 rendered pages; text > 20 MB without highlighting; idle unload 5/15/30/60/never, default 30 min; trim ~1 s after close.
- Window: size by content, clamp [480×320, 80 % of the Explorer monitor work area], centred on that monitor; title bar 48 px; appear 180 ms ease-out, close 120 ms, resize ≤ 150 ms; animations off when `SPI_GETCLIENTAREAANIMATION == FALSE`.
- Default preferred sizes: text 960×720, other 720×540 (DIP).
- Store product ids: HEIF `9PMMSR1CGPWG`, AV1/AVIF `9MVZQVXJBQ9V`, RAW `9NCTDW2W1BH8`, HEVC `9NMZLZ57R3T7`; URI `ms-windows-store://pdp/?productid=<id>`.
- Metrics (spec §9, Private Working Set): Cold ≤ 5 MB; Warm-idle ≤ 25 MB; Space→window (warm) ≤ 50 ms; Space→image/text rendered (warm, ≤ 10 MB / 24 MP) ≤ 150 ms; Space→window (cold, no prewarm) ≤ 400 ms; 24 MP photo ≤ 120 MB total; 1000 open/close: growth ≤ 2 MB, 0 missed spaces, 0 crashes; 24 h with sleep/lock: Space always works.
- Repo `https://github.com/Denmurzik/FastLook`, MIT. Commits: conventional messages, **never** any `Co-Authored-By` or other trailer.
- Never modify the user's PowerToys configuration.
- Coroutines: no reference parameter is used after the first `co_await`; a coroutine member function of a ref-counted object starts with `auto self = shared_from_this();` (or `get_strong()`); the UI thread never waits on I/O or on a cross-process call without a timeout.

```cpp
EncodingInfo DetectEncoding(std::span<const uint8_t> s, uint32_t ansiCp, bool sampleIsPrefix) {
    if (StartsWith(s, {0xFF, 0xFE, 0x00, 0x00}) || StartsWith(s, {0x00, 0x00, 0xFE, 0xFF})) return {TextEncoding::Unsupported, 0, 4};
    if (StartsWith(s, {0xEF, 0xBB, 0xBF})) return {TextEncoding::Utf8, 65001, 3};
    if (StartsWith(s, {0xFF, 0xFE}))       return {TextEncoding::Utf16LE, 1200, 2};
    if (StartsWith(s, {0xFE, 0xFF}))       return {TextEncoding::Utf16BE, 1201, 2};
    if (IsValidUtf8(s, /*allowTruncatedTail=*/sampleIsPrefix)) return {TextEncoding::Utf8, 65001, 0};   // ASCII included
    return {TextEncoding::Ansi, ansiCp, 0};
}
// IsValidUtf8 rejects: C0, C1, F5..FF lead bytes; overlongs E0 80..9F, F0 80..8F; surrogates ED A0..BF; > U+10FFFF (F4 90..);
// a sequence cut by the end of the sample is accepted only when allowTruncatedTail.
```
- Line rules: CR, LF, CRLF end a line (CRLF split across `Append` calls counts once); a run of `kMaxLineUnits` units (bytes for 8-bit encodings — backing off to a UTF-8 lead-byte boundary — or UTF-16 code units, never splitting a surrogate pair) without EOL ends a segment, the next segment has `continuation = true`; only every 64th line start is stored, `Line(n)` scans forward from the checkpoint.

```cpp
HookVerdict HookFilter::Decide(KeySnapshot const& k, FocusSnapshot const* f, HookConfig const& c) noexcept {
    if (k.extraInfo == kInjectedMarker) return HookVerdict::Pass;
    if (k.vk != VK_SPACE) {
        if (k.keyDown && !k.ctrl && !k.alt && !k.win && IsTypeAheadKey(k.vk)) { m_typeThread = k.fgThreadId; m_typeTime = k.timeMs; }
        return HookVerdict::Pass;
    }
    if (!k.keyDown) { m_held = false; bool s = std::exchange(m_swallowing, false); return s ? HookVerdict::Swallow : HookVerdict::Pass; }
    if (m_held) return m_swallowing ? HookVerdict::Swallow : HookVerdict::Pass;          // autorepeat
    m_held = true;
    if (c.paused || !f || !ModifiersMatch(c.key, k)) return HookVerdict::Pass;          // Space: none of Ctrl/Alt/Shift/Win; X+Space: exactly X
    if (f->fg == ForegroundKind::Desktop ? !c.desktopEnabled : f->fg != ForegroundKind::Explorer) return HookVerdict::Pass;
    if (f->guiFlags & (GUI_INMENUMODE | GUI_POPUPMENUMODE | GUI_SYSTEMMENUMODE | GUI_INMOVESIZE)) return HookVerdict::Pass;
    if (f->hasCaret && IsEditClass(f->caretClass)) return HookVerdict::Pass;            // "Edit*", "RichEdit*" (case-insensitive)
    if (!f->focusUnderDefView || !IsItemViewClass(f->focusClass)) return HookVerdict::Pass;  // "DirectUIHWND", "SysListView32"
    if (m_typeThread == k.fgThreadId && k.timeMs - m_typeTime < 1000u) return HookVerdict::Pass;  // uint32 wrap-safe
    m_swallowing = true;
    return HookVerdict::Trigger;
}
```
- Folder window: `total ≤ 20000` → `[0, total)`; else `[max(0, focus−5000), min(total, focus+5001))`.
- `PlanFromSelection`: selection > 1 → mode Selection, items = selection (capped with `FolderWindow` around the focused item's position in it), index = position of `focused` in it or 0, listComplete = true; selection == 1 → mode Folder, items = {selection[0]}, listComplete = false; selection == 0 and focused → mode Folder, items = {focused}, listComplete = false; nothing → nullopt.

```cpp
    case ViewerEvent::PreviewShown:   m_visible = true; m_trimDue = 0; break;
```

```cpp
class ShellWorker {   // owns one STA thread at a time; a timed-out thread is abandoned ("poisoned") and replaced
```

- ShellWorker algorithm:

```cpp
template <class F> auto ShellWorker::Run(F&& fn, std::chrono::milliseconds timeout) -> std::optional<std::invoke_result_t<F>> {
    using R = std::invoke_result_t<F>;
    auto job = std::make_shared<Job<R>>(std::forward<F>(fn));    // mutex + condition_variable + done flag + std::optional<R> result
    if (AbandonedCount() >= kMaxAbandoned) return std::nullopt;  // hung Explorer: fail fast, no unbounded thread growth
    EnsureThread();                                              // spawn STA thread (CoInitializeEx APARTMENTTHREADED) if none alive
    m_thread->Post(job);                                         // queue + PostThreadMessage wake-up; thread pumps messages (COM needs it)
    if (job->WaitFor(timeout)) return std::move(job->result);
    m_thread->Poison();                                          // thread finishes the stuck call later, takes no new jobs, CoUninitialize, exits
    m_thread.reset();                                            // detached (shared state keeps it alive); next Run spawns a fresh thread
    ++m_abandoned; return std::nullopt;
}
```
